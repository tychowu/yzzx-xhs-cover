# 言直在线视频封面 · yzzx-cover

面向真人 IP 的视频封面生成与风格学习 Skill，适配 Codex 与 WorkBuddy。提供文案和人物参考，确认标题与补充素材，选择风格后生成独立封面；兼顾人物身份、文字排版与画面质量，并将用户确认的风格沉淀为可复用规则。

调用名称：`yzzx-cover`。完整执行规则见 [SKILL.md](SKILL.md)，视觉方向可查看[风格展示站](https://yzzxref.diwu-pru.vip/)。

## 核心特色

团队改进与发布请看 [团队使用说明](CONTRIBUTING.md)。当前版本见 [VERSION](VERSION)，更新记录见 [CHANGELOG.md](CHANGELOG.md)：有写入权限的成员直接更新 main，不新建分支、不要求 PR 审批；AI 自动填写修改说明，保留测试和隐私检查，推送后的自动检查通过后发布版本。

- **分级同步版本**：新版正式 Release 自动备份并更新全局 Skill；未发布的 main 更新及普通 pull 仅作用于项目副本，不自动同步全局。本地有修改或版本不明时暂停处理，避免覆盖。此检查在调用时执行，不是后台监控。
- **快速进入制作**：收到“生成一张封面”即开始本期流程，简短收集缺失材料，不长篇复述规则，也不擅自沿用无关上期内容；必要确认仍保留。
- **先确认，再生成**：先收集文案与人物照片，确认主副标题，再推荐 4 种风格供选择；不会把打开网站当成已确认。
- **按选择交付数量**：推荐 4 种不等于自动生成 4 张。默认每种选定风格生成 1 张，也支持同一风格多张测试；每张独立交付，不合成四宫格。
- **人物身份优先**：人物参考图是唯一身份依据，锁定面部骨骼、眼距、颧骨、下颚几何形状，以及发型、眼镜、胡须和服装。风格示意图中的人物不能成为身份来源。
- **自然均匀肤质**：避免皮肤斑驳、黑白色块和过度锐化；保留原有肤色，不以美白代替均匀肤色。女性默认轻微自然磨皮，较深肤色参考增加轻微磨皮与柔和补光，均不得改变五官或塑料化。
- **标题清楚、内容可信**：一个视觉中心，兼顾手机缩略图可读性；不编造数据、官方背书或超出正文的承诺。
- **有边界的质量验收**：逐项检查文字、人物身份、面部几何、肤质、手部和画面完整性；失败项最多修正 3 次。“100%相同”是身份保持目标，不是模型效果保证。

## 制作一张封面

首次生图前会核实当前技能版本；同一任务的多张生成或连续重试不重复询问。详情见[版本检查与更新确认](references/version-check.md)。

1. 提供文案或逐字稿，以及人物照片或多视图控制图；明确不需要人物时可省略照片。
   收齐后会询问是否补充 Logo／图标、其他人物或重要图片。回复“否”继续原流程；上传后，将素材与主角的动作、视线或场景建立符合文案的互动关联，不做无关贴图，也不自动归入风格库。
2. 确认主标题与副标题。已提供的材料不重复索取，已确认文字不因换风格擅自改写。
3. 查看 4 种风格推荐与展示站，选择一种或多种；已明确指定风格时，以用户选择为准。
4. 按确认的风格和数量生成，逐张验收并交付。默认画布为 **3:4、1080×1440**，不得将 2:3 图像拉伸充当 3:4。

奶油巨字风格要求主标题恰好为 4 个中文字符；若已确认标题不符合要求，会先提出修改并再次确认。

```text
请使用 $yzzx-cover 为这期视频制作封面。
文案：……
人物参考：已上传角色控制图。
主标题：……
副标题：……
```

## 学习新风格

学习流程分三阶段，每个阶段有独立确认边界：

1. **Phase 1 · 查看与分析**：查看 1–5 张参考图，分析配色、字体、构图、装饰和氛围，向用户展示方向与名称建议。此时不写 JSON、不复制素材、不更新索引。
2. **Phase 2 · 确认与保存规则**：用户确认分析与名称后，保存风格 JSON、全部学习参考图并更新索引；随后单独询问是否试生成。
3. **Phase 3 · 测试与对比**：明确同意后，收集测试文案与人物控制图，生成并与原参考图对照；不满意时按偏差修改提示词，最多迭代 3 次。

**测试通过不等于自动入库。** 用户确认测试通过后，再询问是否将选定测试图保存为风格示意图。只有确认加入才归档，以风格中文名命名；同名已有文件时新增版本号，不覆盖旧图，源测试图仍保留。

学习参考图、测试图、已确认示意图分别存放，避免把原始参考当成生成结果，或把未确认测试当成正式样式。

## 安装与运行

将完整技能目录复制到以下位置，不能只复制 `SKILL.md`：

```text
~/.codex/skills/yzzx-xhs-cover/        # Codex
<workspace>/.workbuddy/skills/YZZX-cover/   # WorkBuddy（项目级技能目录）
```

> WorkBuddy 调用时名称用小写 `@skill:yzzx-cover`；大写目录名 `YZZX-cover` 不影响文件读取，但按名调用需用小写。WorkBuddy 专属运行差异见 `SKILL.md` 文末「WorkBuddy 环境补充」与 `references/workbuddy-adaptations.md`。

首次运行或迁移后，从技能目录执行环境检查：

```bash
python3 scripts/bootstrap.py --install
```

首次运行还会创建当前登录用户图片目录下的 **Yzzx Cover**，返回绝对路径 `output_root`：macOS 为 `~/Pictures/Yzzx Cover`；Windows 读取系统 Pictures 目录（兼容 OneDrive 重定向），不写死用户名。目录不可用时报告错误，不回退到仓库。也可运行 `python3 scripts/output_paths.py` 单独初始化。

脚本创建独立缓存环境并安装所需 Python 依赖，后续脚本使用检查结果返回的 Python 路径。安装遵循宿主的权限与网络限制；环境检查本身不生图、不上传人物照片、不消耗生成额度。

图片生成优先使用宿主内置工具，该路径不需要另装 OpenAI SDK、Node.js 或提供 API key。可选的 `generate.mjs` 提示词脚本需要 Node.js 18+；其旧版直连 API 路径不自动用于环境检查或付费测试。详细依赖与故障处理见 [SKILL.md](SKILL.md)。无可用生图工具时，交付制作说明，不声称已生成图片。

## WorkBuddy 适配与优化

两个宿主共用标题确认、风格选择、人物身份保持和外置归档规则；WorkBuddy 的工具差异单独处理，不替换 Codex 的生成流程。

- **调用与简短交互**：使用小写 `@skill:yzzx-cover`；按名解析失败时按路径读取 `SKILL.md`。启动制作时仅询问当前最关键的缺失信息，不默认跳过补充素材、标题或风格确认。
- **内置预览**：使用 `present_files` 打开风格展示站，并在成图验收后交付本地图片与预览；工具不可用时如实说明，不把发出链接说成已打开。
- **按需依赖**：内置 ImageGen 不依赖 OpenAI SDK 或 Node；`output_paths.py` 可零依赖初始化外置目录。运行 Python 辅助脚本时使用当前机器可用的托管解释器，不照搬其他电脑的绝对路径。现有 `bootstrap.py` 仍检查 PyYAML，不能把文档中的可选依赖方向当成已实现的自动降级。
- **实测画布**：生成后读取实际像素，校正到 1080×1440 再验收；采用等比缩放配合填充或裁剪，不拉伸人物，并保护文字和脸部。
- **本地看图验收**：内联图片不可见时使用 `Read` 查看本地参考和成图。工具仍不能提供视觉内容时，明确说明未完成视觉验收，不凭提示词宣称合格。
- **水印与文字保护**：提示词避免诱发模型绘制平台文字，并检查四角边缘。仓库提供角落克隆修补脚本处理已观察到的宿主角标；不使用可能连主副标题一起清除的全图文字擦除。修补前检查目标区域、保留原图，修补后复查文字与纹理，不保证所有背景都适用。
- **外置交付**：继续保存到当前用户 Pictures 下的 `Yzzx Cover`，不写入仓库 `output/`，不自动提交生成结果。

以上为仓库已记录的适配经验，具体工具能力以当前 WorkBuddy 会话为准。工具说明与已知限制见 [WorkBuddy 环境适配](references/workbuddy-adaptations.md)。

生成结果单独存放在当前用户的图片目录：

```text
Pictures/Yzzx Cover/
├── covers/<主题>/                   # 普通封面及提示词
└── style-tests/<style-id>/          # 测试及迭代记录
```

仓库保留技能规则、脚本、学习参考图和经用户确认的示意图。**新生成图片和提示词保存到仓库外的 `Pictures/Yzzx Cover`，不提交到 GitHub**。旧 `output/` 不自动搬迁或删除，仍应排除提交；提交前检查 `.gitignore` 包含 `/output/`，并检查暂存列表，不使用强制添加绕过忽略规则。对已跟踪输出取消跟踪不会删除本地文件，也不会清除旧提交中的历史副本。

本 README 是概览；执行时以 [SKILL.md](SKILL.md) 和所选风格 JSON 为准。普通生成或测试不会自动修改技能、替换示意图或发布仓库；可复用规则的回写需用户明确要求。
